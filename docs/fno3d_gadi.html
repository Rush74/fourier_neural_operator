Learning Navier–Stokes as a space–time operator

How this repository trains and runs the 3D Fourier Neural Operator (FNO-3D) on the 2D incompressible Navier–Stokes equations, the mathematics behind each step, and a plan for running it on NCI Gadi's dgxa100 queue.

"3D" means two space dimensions plus time. The model reads the vorticity at the first 10 time steps and predicts the next 40 in a single forward pass. It treats the trajectory \(w(x,y,t)\) on a \(64\times64\times40\) grid as one function and convolves over all three axes in Fourier space.

Mathematics · 1

The PDE and the operator being learned

The benchmark is 2D viscous, incompressible flow on the unit torus \(\mathbb T^2=(0,1)^2\) with periodic boundaries, written in vorticity form (Li et al. 2021, §5.3):

Vorticity–stream-function form
\[ \begin{aligned} \partial_t w(x,t) + u(x,t)\cdot\nabla w(x,t) &= \nu\,\Delta w(x,t) + f(x), && x\in\mathbb T^2,\ t\in(0,T]\\ \nabla\cdot u(x,t) &= 0, && w = \nabla\times u\\ w(x,0) &= w_0(x) \end{aligned} \]
\[ -\Delta\psi = w,\qquad u = \big(\partial_y\psi,\ -\partial_x\psi\big),\qquad f(x)=0.1\big(\sin 2\pi(x_1+x_2)+\cos 2\pi(x_1+x_2)\big) \]

The viscosity \(\nu\) sets the Reynolds number. The paper uses \(\nu=10^{-3}\) (T = 50), \(10^{-4}\) (T = 30) and \(10^{-5}\) (T = 20). The lower values are turbulent and much harder to learn. Initial conditions come from a Gaussian measure with a Matérn-like covariance, so their spectrum decays like \(|k|^{-5}\):

Initial-condition measure (random_fields.py, α = 2.5, τ = 7)
\[ w_0\sim\mu=\mathcal N\!\big(0,\;\tau^{2\alpha-2}\,(-\Delta+\tau^2 I)^{-\alpha}\big),\qquad \hat w_0(k)=\sigma\,\big(4\pi^2|k|^2+\tau^2\big)^{-\alpha/2}\,\xi_k,\ \ \xi_k\sim\mathcal N_{\mathbb C}(0,1) \]

The FNO-3D does not learn one time step. It learns the map from a short history window to the future trajectory:

Target operator
\[ \mathcal G^\dagger:\; w\big|_{\mathbb T^2\times[0,10]}\;\longmapsto\; w\big|_{\mathbb T^2\times(10,\,T]},\qquad \mathcal G_\theta\approx\mathcal G^\dagger\ \text{ by }\ \min_\theta\ \mathbb E_{w_0\sim\mu}\,\frac{\|\mathcal G_\theta(a)-\mathcal G^\dagger(a)\|_{L^2}}{\|\mathcal G^\dagger(a)\|_{L^2}} \]

In fourier_3d.py: T_in = 10 input snapshots and T = 40 output snapshots on a 64 × 64 grid. The time axis is treated as a third spatial coordinate, which is why the Fourier transform is 3D.

Mathematics · 2

Data generation: pseudo-spectral Crank–Nicolson

ns_2d.py integrates the PDE in Fourier space on a 256² grid with \(\Delta t=10^{-4}\), solving a batch of initial conditions at once on the GPU. Each step:

  1. Poisson solve for the stream function. \(\hat\psi_k=\hat w_k / (4\pi^2|k|^2)\), with the \(k=0\) mode guarded (lap[0,0]=1).
  2. Velocity and vorticity gradients by spectral differentiation: \(\widehat{\partial_x}\leftrightarrow 2\pi i k_x\). So \(u=\mathcal F^{-1}(2\pi i k_y\hat\psi)\), \(v=-\mathcal F^{-1}(2\pi i k_x\hat\psi)\).
  3. Nonlinear term in physical space. Compute \(N=u\,\partial_x w+v\,\partial_y w\) pointwise, transform back, then apply Orszag's 2/3 dealiasing rule (zero modes with \(|k_j|>\tfrac23 k_{\max}\)).
  4. Time step. Crank–Nicolson for diffusion, explicit Euler for advection and forcing:
    \[\hat w^{n+1}_k=\frac{\big(1-\tfrac12\Delta t\,\nu\,4\pi^2|k|^2\big)\hat w^n_k-\Delta t\,\hat N^n_k+\Delta t\,\hat f_k}{1+\tfrac12\Delta t\,\nu\,4\pi^2|k|^2}\]
  5. Record record_steps snapshots evenly over \([0,T]\). The published datasets are downsampled to 64² and saved at 1 time unit per snapshot, giving shape [N, 64, 64, T].
Matching the published data

As committed, the script uses N = 20 samples and record_steps = 200 at 256². To reproduce NavierStokes_V1e-3_N5000_T50.mat, set record_steps = 50 (one per unit time), raise N and the batch size, set a seed per run, and subsample u[:, ::4, ::4, :] before training.

Mathematics · 3

The FNO-3D architecture

A neural operator stacks kernel integral layers between a pointwise lifting \(P\) and projection \(Q\) (Kovachki et al. 2023). In the FNO the kernel is a convolution, so the convolution theorem lets it be parameterised directly by its Fourier coefficients \(R_\phi\):

Fourier layer, l = 0 … 3
\[ v_0 = P\big(a(x),\,x\big),\qquad v_{l+1}(x)=\sigma\Big(W_l\,v_l(x)+\big(\mathcal K_l v_l\big)(x)\Big),\qquad u(x)=Q\big(v_4(x)\big) \]
\[ \big(\mathcal K_l v\big)(x)=\int\kappa_l(x-y)\,v(y)\,dy=\mathcal F^{-1}\!\Big(R_l\cdot\big(\mathcal F v\big)\Big)(x),\qquad \big(R_l\cdot\mathcal F v\big)_k=\begin{cases}R_{l,k}\,(\mathcal F v)_k & |k_j|\le k_{\max,j}\\ 0&\text{otherwise}\end{cases} \]

\(R_{l,k}\in\mathbb C^{d_v\times d_v}\) is a learned channel-mixing matrix per retained mode. \(W_l\) is a pointwise linear map, a 1×1×1 Conv3d, which restores the high frequencies the truncation drops. σ is GELU. The last layer has no activation.

Forward pass of FNO3d (shapes for batch B, width 20)

Why four weight tensors: rfftn keeps only non-negative frequencies on the last (time) axis, because the input is real. The x and y axes still hold both signs, so the low modes sit in four corners of the spectrum: \((\pm k_x,\pm k_y,k_t\ge0)\). weights1…4 each have shape [20, 20, 8, 8, 8] (complex).

Cost per layerO(N log N)FFT over \(N=64\cdot64\cdot46\) points, versus \(O(N^2)\) for a dense kernel integral.
Spectral parameters6,553,6004 layers × 4 corners × 20·20·8³ complex weights. Complex counts as 2 reals (commit e5a0838). Total ≈ 6.56 M.
Discretisation invarianceWeights live on modes\(R\) is indexed by wavenumber, not grid point, so the same weights run on a finer grid (zero-shot super-resolution).

Inputs and positional encoding. The 10 input snapshots are copied along the time axis to every one of the 40 output times. get_grid then appends normalised coordinates \((x,y,t)\in[0,1]^3\), giving 13 channels. The lifted function therefore knows where in space-time each point is. Universal approximation results for this architecture are proved by Kovachki, Lanthaler & Mishra (2021).

Workflow · 1

Training

  1. Load. MatReader(path).read_field('u') returns [N, 64, 64, 50]. It uses scipy for v5 .mat files and falls back to h5py for v7.3, reversing the axes. Then a = u[..., :10] and y = u[..., 10:50]. Train on the first ntrain = 1000 samples and test on the last ntest = 200.
  2. Normalise pointwise. UnitGaussianNormalizer stores a mean and standard deviation per grid point and time, computed over the training set:
    \[\tilde a(x)=\frac{a(x)-\bar a(x)}{s_a(x)+\varepsilon},\qquad \tilde y(x)=\frac{y(x)-\bar y(x)}{s_y(x)+\varepsilon},\quad \varepsilon=10^{-5}\]
    Test inputs use the training statistics. Test targets stay in physical units.
  3. Broadcast in time. a.reshape(N,64,64,1,10).repeat([1,1,1,40,1]). Batch size 10, shuffled.
  4. Optimise. Adam(lr = 1e-3, weight_decay = 1e-4), StepLR(step = 100, γ = 0.5), 500 epochs. The loss is the relative L² error after decoding the prediction back to physical units, summed over the batch:
    \[\mathcal L(\theta)=\sum_{j\in\text{batch}}\frac{\big\|\,\mathcal D_y\!\big(\mathcal G_\theta(\tilde a_j)\big)-y_j\big\|_2}{\|y_j\|_2}\]
    The MSE is computed and logged but not back-propagated.
  5. Evaluate each epoch. Run the same relative L² on the test loader under torch.no_grad(). Each epoch prints ep, time, train_mse, train_l2, test_l2.

Workflow · 2

Inference

After training, the script runs every test sample with batch size 1. It decodes the output with the training \(\bar y, s_y\), prints the per-sample relative L², and writes pred/<path>.mat with shape [200, 64, 64, 40]. To use a trained model on new data:

  1. Prepare the input. Take the first 10 snapshots \(w(\cdot,t_1),\dots,w(\cdot,t_{10})\) on a 64² grid at unit spacing in time.
  2. Encode with the training normaliser \((\bar a, s_a)\), then repeat along time to 40.
  3. Forward pass under model.eval() and torch.no_grad(). One pass returns all 40 future snapshots, with no time-stepping loop.
  4. Decode with \((\bar y, s_y)\) to get vorticity in physical units.
Speed (paper, ν = 1e-4, 64²)0.005 s vs 2.2 sFNO per-instance inference versus the pseudo-spectral solver above.
Super-resolution64² → 256²Feed a finer grid. The FFT sizes change but \(R\) does not. See scripts/super_resolution.py.
Normaliser is tied to the grid

UnitGaussianNormalizer stores statistics per grid point, with shape [64, 64, 40], so they will not broadcast onto a 256² input. For super-resolution, interpolate \(\bar a, s_a, \bar y, s_y\) to the new grid or switch to the scalar GaussianNormalizer before training.

Recommended plan

This model is small: about 6.6 M parameters, and roughly 4 GB of data for ν = 1e-3. A full 500-epoch run fits comfortably on one A100, so the best use of the queue depends on the stage:

  • Smoke test: 1 GPU, 20 minutes, 5 epochs, to time an epoch. That costs about 24 SU.
  • Production run for one configuration: 1 GPU, with checkpoint and resume, so a run longer than 48 h can be chained.
  • Sweeps over modes, width, ν or seeds: one full node, running 8 independent runs, one per GPU, in a single job. NCI does not support PBS job arrays on Gadi, so this pattern replaces them.
  • Large data (ν = 1e-4 with N = 10000, or a 128² grid): 8-GPU data-parallel training with torchrun on one node.
  • Data generation: 8 seeded copies of ns_2d.py on one node. It is a fully GPU-resident spectral solver, so it scales across GPUs with no communication.

#PBS -P ab12
#PBS -q dgxa100
#PBS -l ngpus=8
#PBS -l ncpus=128
#PBS -l mem=1000GB
#PBS -l jobfs=200GB
#PBS -l walltime=48:00:00
#PBS -l storage=gdata/ab12+scratch/ab12
#PBS -l wd
#PBS -N fno3d_ddp
#PBS -j oe

module load python3/3.11.7
source /g/data/ab12/$USER/envs/fno/bin/activate
export OMP_NUM_THREADS=16
export NCCL_DEBUG=WARN
cp /g/data/ab12/$USER/fno/data/NavierStokes_V1e-4_N10000_T30.mat $PBS_JOBFS/
cd /g/data/ab12/$USER/fno/code

torchrun --standalone --nproc_per_node=$PBS_NGPUS \
  fourier_3d_gadi.py --data $PBS_JOBFS/NavierStokes_V1e-4_N10000_T30.mat \
  --out /scratch/ab12/$USER/fno/runs/v1e-4_ddp --ntrain 9800 --ntest 200 \
  --t-in 10 --t 20 --batch 10 --lr 4e-3   # per-GPU batch; global = 80

With 8× the global batch, scale the learning rate (start near 4e-3 to 8e-3 with a short warm-up) or keep a global batch of 10 and accept less speed-up. Two-node jobs (256 cores) are limited to 5 h, so use them only if one node is too slow.

  --data $PBS_JOBFS/NavierStokes_V1e-3_N5000_T50.mat \
  --out  /scratch/ab12/$USER/fno/pred/v1e-3_m8_w20.mat
infer_fno3d.py
s = torch.load(ckpt, map_location='cuda'); a = s['args']
model = FNO3d(a['modes'], a['modes'], a['modes'], a['width']).cuda()
model.load_state_dict(s['model']); model.eval()
(am, asd), (ym, ysd) = [(m.cuda(), sd.cuda()) for m, sd in (s['a_norm'], s['y_norm'])]

w_in = MatReader(path).read_field('u')[..., :10].cuda()          # [B, 64, 64, 10]
x = ((w_in - am) / (asd + 1e-5)).unsqueeze(3).expand(-1, -1, -1, 40, -1)
with torch.no_grad():
    pred = model(x).squeeze(-1) * (ysd + 1e-5) + ym              # [B, 64, 64, 40]
scipy.io.savemat(out_path, {'pred': pred.cpu().numpy()})

Inference is milliseconds per sample, so this 30-minute dgxa100 job (about 36 SU) handles thousands of trajectories. Read ckpt, path and out_path from argparse as in step 3. Batch the inputs (for example 50 at a time) to keep the GPU busy.

Storage checklist

Every filesystem a job touches must be listed in #PBS -l storage=, or the job cannot see it. Keep code and the venv on /g/data, put run outputs on /scratch (purged after a period of no access), and stage input .mat files to $PBS_JOBFS at job start.
